Heroku Handbook

Installation, first login, built-in commands and Python with .e. Beta and dev have their own chapters.

What is a userbot?

A regular Telegram bot has its own account. A userbot signs in as you and handles commands you send from your account. For example, .ping shows response time. You can send commands in Saved Messages, a private chat or a group, subject to the permissions you have there.

Heroku is a fork of Hikka. It uses herokutl, a Telethon fork. It redirects imports of telethon and hikka inside external modules to its own packages, which helps with compatibility. It does not guarantee that every older module works unchanged.

What it can do

  • Run built-in commands for translation, diagnostics, backups and Python evaluation
  • Install modules with more commands from a repository or a Python file
  • Display menus and confirmation buttons through a personal inline bot
  • Manage permissions for commands, chats and other users
  • Switch the interface language, including Russian and English

Where data lives

A local installation keeps API credentials in config.json, the Telegram session in sessions/, account settings in config-<id>.json, and external modules in loaded_modules/. Docker stores data under /data. Keep those files private, especially the session.

One rule

Do not send anyone your session files or commit them to a public repository. A session file can let someone connect to your account without requesting a new login code.

Installation →

Installation

You need Python 3.10 or newer, git and a machine that can keep Heroku running.

Where to run it

A VPS is the straightforward choice for round-the-clock use. A home computer works while it is powered on. Termux on Android is possible, but Android may stop the process to save battery. Windows users can use WSL; the project's README calls that route less stable.

Ubuntu and Debian

terminal
sudo apt update && sudo apt install git python3 python3-venv -y
git clone https://github.com/coddrago/Heroku
cd Heroku
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m heroku

The virtual environment keeps Heroku's Python dependencies separate from the rest of your system. Fedora uses sudo dnf install git python3 -y for the first line; Arch uses sudo pacman -S git python --needed. The remaining steps are the same.

Installer script

The repository also includes install.sh. It detects apt, pacman, dnf, Homebrew or Termux, installs dependencies, creates a virtual environment and starts Heroku.

terminal
git clone https://github.com/coddrago/Heroku
cd Heroku
bash install.sh

On failure it prints heroku-install.log to the terminal. It removes that log after a successful installation.

Docker

terminal
git clone https://github.com/coddrago/Heroku
cd Heroku
bash docker.sh

The script builds an image and starts an interactive setup. After login, use docker-compose up -d. The named worker volume persists data under /data. To build a dev image, use docker-compose build --build-arg HEROKU_REF=dev, then restart the container.

Keeping it running

For a normal installation, start from the Heroku directory with source .venv/bin/activate followed by python3 -m heroku. Closing that terminal stops the process. On a VPS you can keep it alive in screen or tmux; Docker users can run the container detached.

Heroku warns when run as root. Use a separate system user if possible. Pass --root only when you knowingly want modules to run with root privileges.

First login

Have your API ID and API hash ready before you start.

Get your API credentials

  1. Sign in at my.telegram.org. Telegram sends the code to the app
  2. Open API development tools and create an application
  3. Copy App api_id (a number) and App api_hash (32 hexadecimal characters)

Enter them when Heroku asks. It saves them to config.json. Do not publish the API hash.

Sign in with QR or phone

The prompt Use QR code? [y/N] offers two routes. For QR login, scan the code displayed in the terminal from Telegram's device settings. For phone login, enter your number in international format and then the code Telegram sends to your app. If two-step verification is enabled, enter its cloud password when asked. Password characters are not displayed while typing.

The session is saved as sessions/heroku-<your_id>.session, so subsequent launches normally do not ask for a code.

Your inline bot

Heroku uses a personal bot created through @BotFather for inline forms, galleries and confirmation buttons. When asked for a username, you can leave it blank to use an automatically generated one. A custom name must end in bot. The prompt can appear at a different point depending on the login route; with QR login Heroku may simply choose a name for you. You can later change it with .ch_heroku_bot or set a token with .ch_bot_token.

After login

Heroku creates a private heroku-userbot channel for backups and service files. Its inline bot may send a welcome message with language choices and ask how often to make backups. To check that commands work, send .ping to Saved Messages.

Files, backups and migration

You can reinstall Python dependencies. Your session and account database are the files you need to protect and keep.

PathWhat it holdsMigrate?
config.jsonAPI credentials and device nameYes, privately
sessions/Telegram authorizationYes, if you want to avoid a new login
config-<id>.jsonSettings and data for that accountYes
loaded_modules/External module filesYes, especially modules installed from files

Moving to another server

  1. Stop Heroku on the old server so the same session is not active in two places
  2. Transfer the project and the files above over a protected connection
  3. Create a new virtual environment and install requirements.txt on the new server
  4. Start Heroku and check .ping

.backupall saves the database and external modules, but not a replacement Telegram session or your API credentials. If you migrate using only its archive, you will need to log in again.

Finding backups

The private service channel has a Backups topic. .backupdb, .backupmods and .backupall normally send files there and return a link. Check each command's response if the topic is unavailable.

The basics

A command is a message beginning with a prefix. The default prefix is a dot.

in any chat
.help
.ping
.tr es Hello

After the prefix comes the command name, then its arguments. In command help, <angle brackets> mean required input and [square brackets] mean optional input. Use the spelling shown by .help.

Replies

Some commands take a message to work on from your reply. Reply to a message with .tr en to translate its text. With .e, the replied-to message is available through r.

Change the prefix

in Telegram
.setprefix !

Commands now use !. Ask your inline bot for /profile if you forget the prefix; it displays the current value and a reset button. Longer prefixes require the allow_nonstandart_prefixes setting.

Aliases and disabling commands

.addalias p ping adds a short command .p. Check saved aliases with .aliases and remove one with .delalias p. To temporarily disable a command use .togglecmd name; .togglemod ModuleName toggles a whole module. Run the same toggle again to restore it.

Take care with code

.e runs Python and .terminal runs shell commands on the machine hosting Heroku. Neither is a sandbox for snippets someone sent you.

Everyday tasks

You do not need to memorize the entire command list. These are useful starting points.

Find a command

Send .help and choose a module. For example, .help Translator lists its translation commands. Installed external modules appear in the same help menu.

Translate a message

Reply to the text and send .tr en. To translate text written in the command itself, try .tr es Hello. Choose Telegram or Google as the provider in Translator's .config settings.

Install a module

After the loader's first-time verification, .dlmod lists available names and .dlmod ModuleName installs one from a repository. For a Python file, upload it and reply with .loadmod. .loadmod does not take a URL as a text argument. Check .help afterward.

Read an error

.logs opens a level picker. Start with Error. For more detail choose Debug; .logs debug -f sends it without the extra private-data confirmation. Review the log before sharing it.

Update or disable something

Create a backup with .backupall before .update. On dev, updates display a confirmation when inline is available; the studied master handles confirmation differently. .restart restarts without updating. .togglemod ModuleName temporarily disables a module, while .watcherbl ModuleName disables its watcher in the current chat.

Give limited access

.tsec user @username ping 1h offers to allow that user to run ping for one hour. Use .security for broader settings. .owneradd grants much more access than is needed for one command.

Inline bot and access

The personal inline bot handles forms and buttons. The security system controls who may run commands and press those buttons.

Why there is a second bot

Commands come from your own account, but Telegram needs a bot for inline forms. Heroku configures one through @BotFather. It displays .config menus, confirmations, galleries and paginated lists. Send /profile to that bot to check your prefix or reset it.

Who can run commands?

Your outgoing commands pass the permission check. Other users have no default access. Open .security for global permissions, .security command_name for a particular command and .inlinesec for inline handlers. .querysec toggles queries from other users.

One temporary rule

.tsec user @username ping 1h offers to grant one person the ping command for an hour. Run .tsec without arguments to list active rules. You can also target a chat or a security group.

Chat blocks and watchers

.blacklist blocks a chat and .unblacklist restores it. If a background watcher is noisy in one chat, run .watcherbl ModuleName there instead of removing the whole module.

Co-owner access

.owneradd grants broad permissions. For one or two commands, a targeted .tsec rule is usually a better fit.

.e: Python in chat

Write a Python expression after .e. Heroku evaluates it using meval inside the running userbot process and sends back the result.

Saved Messages
.e 2 + 2
.e "hello".upper()
.e await client.get_me()
.e print("hello from Python")

Top-level await works, print() output is captured, and Heroku displays execution time. The code is real Python running with Heroku's permissions, not a sandbox. The evaluator masks several known secrets in its output, but do not rely on that to safely run code from strangers.

If you send .e with no code while replying to a text message, Heroku tries to evaluate the replied-to text. Read it first.

What is r?

r is the same object as reply, returned by await message.get_reply_message(). Reply to a message and send .e r.text. With no reply, both names are None, so r.text raises an error.

The reference below was checked against the installed herokutl 2.1.0 Message class used by master. Dev depends on herokutl 2.2.0.dev2 and may provide additional rich-message behavior. Properties are read without await; async methods require it.

Examples and common mistakes

reply to the target message
.e len(r.raw_text or "")
.e len((r.raw_text or "").split())
.e r.file.name if r.file else "No file"
.e (await r.get_sender()).first_name
.e await r.reply("Got it")
.e await r.forward_to("me")
.e await r.link()
.e await r.react("👍")
.e await r.download_media()

r.raw_text may be None, so the counting examples use or "". r.file.name fails without an attached file. Even get_sender() may return None. You cannot edit someone else's message merely because you obtained it through a reply.

Output and other languages

-so suppresses the usual result: .e -so await r.delete(). Evaluator displays Python errors with a traceback and blocks db.set("heroku.security", "owner", ...). The masking of known secrets is a backup measure, not a security boundary.

For other languages use .ecpp (C++), .ec (C), .ers (Rust), .eg (Go) or .enode (JavaScript). Their compilers or runtimes must be installed separately. They do not provide the Python variable r.

Writing a module

A module is a Python file defining a class derived from loader.Module. Upload the file to Telegram and reply to it with .loadmod.

A minimal command

hello.py
from heroku import loader, utils


@loader.tds
class HelloMod(loader.Module):
    """A small greeting module"""

    strings = {"name": "Hello"}

    @loader.command()
    async def hello(self, message):
        """Send a greeting"""
        await utils.answer(message, "Hello")

The command becomes .hello. The method docstring is shown in help. Alternatively, name the method hellocmd, whose cmd suffix is removed from the command name.

Arguments and a reply

utils.get_args_raw(message) returns the text after the command. utils.get_args(message) splits it into arguments. await message.get_reply_message() retrieves the message being replied to:

inside a module class
@loader.command()
async def wordscmd(self, message):
    """Count words in a reply"""
    reply = await message.get_reply_message()
    if not reply:
        await utils.answer(message, "Reply to a text message")
        return
    await utils.answer(message, str(len((reply.raw_text or "").split())))

Configuration and saved data

inside a module class
def __init__(self):
    self.config = loader.ModuleConfig(
        loader.ConfigValue(
            "greeting", "Hello", "Text to send",
            validator=loader.validators.String(),
        ),
    )

This appears in .config and can be read with self.config["greeting"]. For module-owned persistent data use self.get("key", default) and self.set("key", value). self.pointer gives an auto-saving list or dict wrapper.

Watching messages and scheduling work

inside a module class
@loader.watcher("in", "only_messages", "no_commands")
async def watcher(self, message):
    if "hello" in (message.raw_text or "").lower():
        await message.reply("Hello")

@loader.loop(interval=300, autostart=True)
async def ticker(self):
    await self.client.send_message("me", "Five minutes passed")

The watcher tags restrict it to incoming messages, excluding service events and userbot commands. A loop's interval is measured in seconds. A watcher replying to every message can quickly hit Telegram rate limits, so narrow its conditions.

Buttons and lifecycle

self.inline.form(text="Menu", message=message, reply_markup=[{"text": "Close", "action": "close"}]) creates an inline form when the personal inline bot is available. Button callbacks receive an object with answer(), edit(), delete() and unload().

Use client_ready after the Telegram client becomes available, config_complete after configuration loads and on_unload for cleanup. A loader.LoadError("reason") raised during loading tells the user why the module cannot run. Module objects provide self.client, self.db, self.inline, self.lookup, self.tg_id and self.get_prefix().

File metadata and libraries

at the top of a module file
# meta developer: @username
# requires: requests
# scope: heroku_min 2.1.0

__version__ = (1, 0, 0)

The loader reads these lines to display the developer, install a pip dependency and check minimum Heroku version. Older telethon, hikkatl and hikka imports are redirected to Heroku's packages; test older modules anyway. Shared libraries can be loaded with self.import_lib(url) and need a loader.Library subclass whose name ends in Lib.

For working examples, read heroku/modules/translate.py and heroku/modules/test.py in the branch you are targeting.

← .e and replyBeta →

Beta

The public testing branch for the next release. At the date of this handbook, origin/beta and origin/dev both pointed to commit dba41c58. Their code was identical then.

Why use beta?

It lets testers try changes before they reach master. It is not a promise of stability or a separate feature set from dev at the studied commit.

Upsides

  • New RichText and prefix features before master
  • Fixes that have not yet shipped in a stable release
  • A chance to test your own modules against the next version

Trade-offs

  • Beta-tester check at startup
  • Changes can break older modules
  • Some master commands, including presets, are gone
  • Depends on herokutl==2.2.0.dev2

The tester check

Dev and beta fetch an allowed-ID list from coddrago/modules-web. If your account is not on it and the checked-out branch is not an ancestor of origin/master, Heroku attempts to reset the working tree to master and restarts. Do not switch branches while keeping uncommitted work in the Heroku checkout.

A bug in this code path

After the reset it attempts self.client.log_out(), but the launcher does not create self.client. The exception is caught. Thus logout is not guaranteed in the studied commit; the reset attempt and restart can still happen.

Install beta

For accounts with testing access, clone the repository and check out beta before installing dependencies:

terminal
git clone https://github.com/coddrago/Heroku
cd Heroku
git checkout beta
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m heroku

On an existing installation, stop Heroku, create a backup with .backupall, run git fetch origin and git checkout beta, activate your virtual environment, reinstall requirements and start Heroku. The dev page describes the currently shared changes in detail.

Dev branch

The studied dev commit reports Heroku 2.2.2 and herokutl==2.2.0.dev2. Beta pointed to the same commit at the time of writing; their names do not imply a code difference right now.

Changes you will notice

Prefixes and command conflicts

.setprefix . ! ? gives the owner multiple prefixes, the first being primary. People who already have permissions can receive a personal prefix with .setprefix --user 123456789 !. If installed modules claim the same command, Heroku offers a choice instead of silently replacing one.

Module cache and updates

External modules are cached on disk. When an ordinary module changes upstream, the loader can offer an update. Built-in updates and URLs you have marked for automatic updates do not ask again. Check the source when approving changed code.

RichText and terminal

Some built-in modules have a rich_mode setting for newer Telegram rich messages. Forms can use self.inline.form(..., rich_message=...). Sudo password input in Terminal moved from editing a Saved Messages message to an inline form that passes the password to the process. .kill is an alias for .terminate.

Logs and hardening

Logs can be routed per account, and .logs ModuleName filters by module. Known session strings, phone numbers and tokens are masked in logs. The database/config are written via private temporary files, the session directory receives restricted permissions, and the bot checks its private service channel before reusing it for backups. Code-download URLs are validated more strictly.

For module authors

  • self.create_task(coroutine) tracks tasks so unloading a module can clean them up
  • The Hidden config validator registers values as secrets
  • Forms gain rich_message and reply_to; additional utilities expose memory, swap and rich output helpers
  • The old _send_stats block was removed

Removed or changed commands

presets.py is gone, so .presets, .loadpreset, folder commands and alias-file commands are absent. .fcfg was removed. .cfg Module option value still works on dev: it is now an alias of .config, whose handler also accepts direct values.

Switch to dev or back

Stop Heroku and back up your data first. In its directory, with the virtual environment active:

terminal
git fetch origin
git checkout dev
pip install -r requirements.txt
python3 -m heroku

To return, replace git checkout dev with git checkout master and reinstall requirements. The database and sessions are outside Git, but switching does not replace a backup. Docker supports docker-compose build --build-arg HEROKU_REF=dev.

Tester gate

version.check_branch runs during startup on dev. Without a permitted account ID it may try to restore master and restart before normal commands load. The attempted logout contains the bug explained on the Beta page.

Troubleshooting

Start with terminal output and .logs. The last line of an error often identifies the problem.

Heroku warns about running as root

Use a regular system user. If running as root is intentional, start with python3 -m heroku --root. External modules will then have root privileges too.

Python 3.10 or newer is required

Check python3 --version. Install a newer version, recreate .venv with that Python, then reinstall requirements.txt.

“Check that this is the only instance running”

Another process has the session file open. Stop the duplicate. If you used screen, reconnect with screen -r heroku rather than starting a second copy.

API ID or hash is rejected

Check that both values are from the same application on my.telegram.org. Replace the incorrect config.json values and run setup again.

Telegram reports FloodWait

Wait for the period stated in the error before trying again. Repeated login attempts may make it longer.

The Telegram session stopped working

Check Telegram's device list. If you revoked the session or used the same file concurrently on two machines, sign in again.

The inline bot was not created

@BotFather may limit new bots. You can use an existing bot via .ch_heroku_bot and .ch_bot_token. Keep its token private.

Commands do not respond

Check that the process is running, the command comes from the authorized account, and you are using the current prefix. Your inline bot's /profile shows the prefix. A chat blacklist can also block commands.

A module will not load

Open .logs for the cause: missing dependency, incompatible version, code error or unavailable inline bot. Try disabling the failing module before resetting the whole installation.

I want to start from scratch

Save a backup first. python3 -m heroku -w asks for confirmation and removes config, sessions and installed modules. .cleardb clears only the database.

Getting help

.support sends the project's support links. Review logs for private data before posting them in a public chat.
