Heroku Handbook

Установка, первый вход, встроенные команды и Python через .e. Отдельно разобраны ветки master, beta и dev.

Что такое юзербот

Обычного бота создают через @BotFather, и он пишет от своего имени. Юзербот устроен иначе: программа входит в Telegram под вашим аккаунтом и реагирует на ваши же сообщения. Например, .ping покажет задержку. Команды можно отправлять в Избранном, личке или группе, но доступ зависит от прав в конкретном чате.

Heroku это один из таких юзерботов, форк проекта Hikka. Внутри стоит библиотека herokutl, форк Telethon с новым слоем протокола Telegram. У Heroku есть совместимость со многими модулями Hikka, FTG и GeekTG: импорты telethon и hikka внутри модулей она подменяет на свои. Это помогает со старым кодом, но не обещает работу каждого модуля без правок.

Что она умеет из коробки

  • Команды с точкой в любом чате: пинг, инфо, перевод, калькулятор, код на Python прямо в сообщении
  • Модули: маленькие программы, добавляющие свои команды. Ищутся через .dlmod по имени или передаются Python-файлом через .loadmod
  • Меню и настройки на инлайн-кнопках через персонального бота, которого Heroku создает сама
  • Резервные копии базы и модулей, автообновления, логи с цензурой секретов
  • Права доступа: можно пустить друга к части команд или дать ему совладение
  • Несколько языков интерфейса, включая русский

Где живут настройки

При обычной установке после первого входа рядом с кодом появляются config.json с API-ключами, папка sessions/ с Telegram-сессией, config-<id>.json с настройками аккаунта и loaded_modules/ со сторонними модулями. В Docker данные лежат в /data; путь можно изменить флагом --data-root. Копируй их только в защищенное место.

Честно о минусах

  • Пока выключен сервер или компьютер, бот не отвечает. Ему нужно место, где он крутится постоянно
  • Сторонний модуль это чужой код рядом с вашей сессией. Ставите наугад, рискуете аккаунтом и данными
  • Telegram формально не поощряет автоматизацию аккаунтов. Пользуйтесь головой, не спамьте
Главное правило

В папке sessions хранится авторизация Telegram, а в config*.json настройки и ключи. Не отправляй эти файлы посторонним и не добавляй их в публичный репозиторий: файл сессии позволяет подключаться к аккаунту без нового кода подтверждения.

Ubuntu и Debian

Самый распространенный путь. Скопируйте весь блок одной командой:

терминал
sudo apt update && sudo apt install git python3 python3-venv -y
git clone https://github.com/coddrago/Heroku
cd Heroku
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m heroku

Первая строка ставит git и Python, вторая скачивает репозиторий. Затем создается виртуальное окружение, отдельная папка с библиотеками Heroku. Последняя строка запускает программу.

Fedora

git clone https://github.com/coddrago/Heroku && cd Heroku
python3 -m venv .venv && source .venv/bin/activate

Установщик install.sh

Ленивый вариант, который сам определяет систему и делает всё перечисленное. Понимает apt, pacman, dnf, brew и Termux. Требует Python 3.10 или новее, иначе откажется работать.

терминал
git clone https://github.com/coddrago/Heroku
cd Heroku
bash install.sh

Если установка упала, скрипт выведет содержимое heroku-install.log в терминал. При успешной установке он удаляет этот файл. Переменные HEROKU_REPO_URL и HEROKU_VENV_DIR позволяют подменить адрес репозитория и путь к окружению.

Android через Termux

Ставьте Termux из F-Droid, сборка из Google Play устарела. Внутри выполняется тот же install.sh, пакеты он поставит через pkg. Дальше главное: откройте настройки Android, найдите Termux и отключите для него экономию батареи, иначе система будет убивать процесс, и бот начнет пропадать из сети.

Docker

терминал
git clone https://github.com/coddrago/Heroku
cd Heroku
bash docker.sh

Скрипт при необходимости поставит docker и docker-compose, соберет образ и запустит первый вход в интерактивном режиме. Для постоянной работы после входа: docker-compose up -d. Данные живут в томе worker, смонтированном в /data, поэтому переживают пересоздание контейнера.

Для beta или dev укажи ветку при сборке: docker-compose build --build-arg HEROKU_REF=dev. Dockerfile принимает этот аргумент, после сборки запусти контейнер заново.

Windows

Нативной версии нет. Официальный путь это WSL: в PowerShell от администратора выполните wsl --install -d Ubuntu-22.04, перезагрузитесь, откройте Ubuntu и дальше действуйте как в разделе про Ubuntu.

Про root

Программа предупреждает о запуске под root и предлагает перейти на обычного пользователя. Модули исполняют Python-код, и под root они получат права на весь сервер. Создать отдельного пользователя можно так:

терминал
adduser heroku
usermod -aG sudo heroku
su - heroku

И ставьте бота уже под ним. Если root действительно нужен, к запуску добавляется --root. В Docker запуск под root уже предусмотрен командой контейнера.

Как запускать после перезагрузки

Две строки из папки с ботом:

терминал
source .venv/bin/activate
python3 -m heroku

Чтобы бот жил после закрытия терминала, запустите его внутри screen:

терминал
sudo apt install screen -y
screen -S heroku
source .venv/bin/activate
python3 -m heroku

Затем Ctrl+A и D, окно отсоединится, процесс останется. Вернуться: screen -r heroku. В Docker вместо этого просто docker-compose up -d.

Первый запуск

Программа задаст пять вопросов. Вот что каждый из них значит и что отвечать.

1. Цветной ли терминал

Появится строка про быструю лису и вопрос, цветная ли она. Ответьте y, если видите цвета, иначе n. Влияет только на раскраску вывода.

2. API ID и API hash

Два ключа, без которых Heroku не войдет в Telegram. Берутся бесплатно на официальном сайте.

  1. Зайдите на my.telegram.org, войдите по номеру. Код придет в чат Telegram, не по СМС
  2. Откройте пункт API development tools
  3. Создайте приложение. Название и короткое имя любые, например myheroku, платформа Other
  4. Со страницы скопируйте App api_id (число) и App api_hash (строка из 32 символов)

Вставьте их, когда программа попросит. Она проверит формат: id должен быть числом, hash строкой из 32 hex-символов. Значения сохранятся в config.json, повторно их вводить не придется.

Секрет

API hash не показывайте в скриншотах и не отдавайте никому под предлогом «а мне для настройки».

3. Как войти: QR или телефон

Вопрос Use QR code? [y/N]. Оба способа одинаково рабочие.

  • QR. В терминале нарисуется код. На телефоне: Настройки, Устройства, Привязать устройство, навести камеру. Код сам перерисовывается каждые десять секунд. Удобно, когда телефон рядом с экраном
  • Телефон. Номер в международном формате, например +79001234567, без пробелов и скобок. Затем код из чата Telegram. Способ удобнее по ssh, когда камерой никуда не наведешь

После входа сессия сохраняется в sessions/heroku-<ваш_id>.session. Все последующие запуски подхватывают её сами.

4. Пароль двухфакторки

Если включена двухэтапная проверка, программа спросит облачный пароль и покажет вашу подсказку в скобках. Символы при вводе не отображаются, так и должно быть. Печатайте и жмите Enter.

5. Имя инлайн-бота

Heroku настроит через @BotFather персонального бота для меню и кнопок. Можно просто нажать Enter, имя придумается автоматически. Свое имя должно заканчиваться на bot, программа проверит, не занято ли оно. На разных путях входа запрос имени появляется в разный момент; при QR он может не появиться вообще, тогда Heroku выберет имя автоматически.

Зачем он нужен: через него работают инлайн-формы, галереи и кнопки подтверждения. Если бот не настроился, эти части интерфейса могут не открываться. Позже имя и токен меняются командами .ch_heroku_bot и .ch_bot_token.

Что произойдет после входа

  • Создается приватный канал heroku-userbot. Это служебное хранилище для бэкапов, логов и медиа галерей. Не удаляйте его и не зовите туда людей
  • Персональный инлайн-бот может прислать приветствие с выбором языка и отдельное предложение настроить период резервных копий
  • В терминале напечатается логотип: версия, хеш сборки, статус обновления и текущий префикс
Проверка

Откройте Избранное и отправьте .ping. Сообщение превратилось в карточку с цифрами, значит всё работает.

Файлы, бэкап и перенос

После входа Heroku хранит авторизацию и настройки на диске. Вот что стоит сохранить перед переездом, а что можно поставить заново.

Перенос на другой сервер

  1. Останови Heroku на старой машине. Одна и та же сессия не должна работать одновременно в двух местах
  2. Скопируй папку проекта вместе с config.json, sessions/, config-<id>.json и loaded_modules/ по защищённому соединению
  3. На новом сервере установи Python, создай .venv и поставь зависимости из requirements.txt
  4. Запусти python3 -m heroku и проверь .ping в Избранном

Через .backupall можно сохранить базу и модули в служебный канал. Этот архив не заменяет файл сессии и API-ключи. Если переносишь только бэкап, Telegram попросит войти заново.

Где искать резервные копии

Heroku создаёт приватный канал heroku-userbot с темой Backups. Команды .backupdb, .backupmods и .backupall сохраняют там файлы и отвечают ссылкой. Если тема недоступна, проверь ответ самой команды: способы отправки отличаются в зависимости от типа бэкапа.

Не пересылай сессию

Архив сессии и база аккаунта содержат личные данные. Для помощи в чате поддержки обычно нужен лог ошибки, а не sessions/ и не config.json.

Основы

Как подаются команды, куда их писать и что делать, если точка мешает переписке.

Анатомия команды

Команда это обычное сообщение, начинающееся с префикса. По умолчанию это точка. Дальше идет имя команды, потом аргументы через пробел.

структура
.tr ru Hello world
 ^  ^  ^^^^^^^^^^^
 |  |  аргументы
 |  имя команды
 префикс

Имена команд регистрируются в нижнем регистре; если сомневаешься, пиши так, как показано в .help. В справке обязательные аргументы пишут в угловых скобках <так>, необязательные в квадратных [так].

Куда писать

Для первых команд удобно Избранное: там ты никому не мешаешь. В группах команды тоже работают, если у аккаунта есть нужные права. Исходное сообщение команды там могут успеть увидеть другие участники.

Реплай как аргумент

Некоторые команды берут объект для работы из реплая. Ответьте на чей-то текст и напишите .tr ru: переведется именно он, аргументы не нужны. Команда .e дает доступ к сообщению из реплая через переменную r.

Сменить префикс

Точка в начале предложения иногда запускает команду случайно. Меняется одной командой:

в любом чате
.setprefix !

После этого команды можно писать с ! вместо точки. Обычно префикс состоит из одного символа; длинный разрешается настройкой allow_nonstandart_prefixes через .config. Забыли, какой поставили: напишите своему инлайн-боту /profile, он покажет префикс и даст кнопку сброса на точку.

Алиасы

Короткая кличка для команды, которую вы часто пишете:

в любом чате
.addalias п ping
.п
.aliases
.delalias п

Первая строка создает алиас, вторая уже работает как .ping. Третья показывает все ваши алиасы, четвертая удаляет один, а .delalias -c чистит весь список.

Выключать ненужное

Команда или модуль надоедают, а удалять жалко: .togglecmd имя_команды гасит одну команду, .togglemod ИмяМодуля целый модуль. Те же команды возвращают всё обратно. Имя модуля берется из .help.

Две команды, с которыми не шутят

.e исполняет Python, .terminal выполняет команды на сервере. Даже одна своя строка может изменить данные или удалить файл, а чужой код тем более не стоит запускать, пока не разобрался, что он делает.

Повседневные задачи

Не надо заучивать весь список команд. Вот несколько сценариев, с которыми проще освоиться после первого .ping.

Найти нужную команду

Вызови .help, выбери модуль и посмотри его команды. Например, .help Translator покажет переводчик. Поставленные сторонние модули появятся в том же списке. Если знаешь команду, но не помнишь синтаксис, справка модуля подскажет аргументы.

Перевести сообщение

Ответь на сообщение и отправь .tr ru. Код языка после команды указывает, на какой язык переводить. Для собственного текста напиши .tr en Привет. Провайдер Telegram или Google выбирается в настройках Translator через .config.

Поставить модуль

После проверки от загрузчика команда .dlmod покажет список имен, .dlmod ИмяМодуля попробует установить выбранный. Если прислали Python-файл, ответь на него командой .loadmod. Ссылку на файл как аргумент .loadmod не принимает. Появился ли модуль, проверь через .help.

Посмотреть ошибку

Напиши .logs и выбери Error в меню. Если нужны подробности, выбери Debug. Команда .logs debug -f отправит его без отдельного предупреждения о приватных данных. Перед тем как передать файл кому-то ещё, просмотри содержимое.

Обновить и сохранить данные

Сначала .backupall, затем .update. На dev бот предложит подтвердить обновление кнопкой, если инлайн-бот работает. На изученном master обработка подтверждения устроена иначе; смотри ответ команды, а не рассчитывай на одинаковый экран. Если нужна только перезагрузка без обновления, есть .restart.

Остановить мешающий модуль

.togglemod ИмяМодуля отключит его, повторная команда включит обратно. Если мешает только слежение за сообщениями в одном чате, попробуй .watcherbl ИмяМодуля прямо в этом чате. Для одной команды есть .togglecmd имя.

Дать доступ другому человеку

Для одной команды на ограниченное время используй точечное правило, например .tsec user @username ping 1h. Для более широких прав есть .security и группы безопасности. .owneradd выдаёт совладение, поэтому для простого доступа к пингу оно избыточно.

Инлайн-бот и права

Инлайн-бот обслуживает формы и кнопки. Система прав решает, кто может запускать команды и нажимать эти кнопки.

Зачем отдельный бот

Обычные команды отправляет твой аккаунт, но Telegram требует отдельного бота для инлайн-форм. Поэтому при установке Heroku настраивает его через @BotFather. Через него работают меню .config, подтверждения, галереи и страницы списков.

Сообщение /profile этому боту показывает префикс и кнопки перезапуска и сброса префикса. Команды .ch_heroku_bot и .ch_bot_token меняют его имя и токен. Токен, как и сессию, не отправляй посторонним.

Кому доступны команды

Исходящие команды владельца проходят проверку прав. Чужим пользователям доступ по умолчанию не выдается. При необходимости открой .security для общего ограничения прав или .security имя_команды для отдельной команды. Для инлайн-команды есть .inlinesec, а .querysec переключает доступ посторонних к инлайн-запросам.

Точечное разрешение

.tsec user @username ping 1h предложит выдать пользователю команду ping на час. Можно выдавать доступ к целому модулю или инлайн-команде, а целью делать пользователя, чат либо группу безопасности. Посмотреть действующие правила поможет .tsec без аргументов.

Чёрные списки и ватчеры

Команда .blacklist ограничит работу в чате, .unblacklist вернёт её. .blacklistuser запретит пользователю доступные ему команды. Если мешает фоновая реакция конкретного модуля на сообщения, .watcherbl выключит её в текущем чате, не удаляя модуль.

Совладение

.owneradd даёт широкие права. Для доступа друга к паре команд начни с .tsec или настрой права этих команд отдельно.

.e: Python прямо в чате

.e это Python-консоль в Telegram. Написали выражение, Heroku выполнила его и вернула результат сообщением. Код исполняется настоящим интерпретатором Python.

Как работает .e

Heroku передает ваш код библиотеке meval, которая вычисляет Python-выражение внутри уже работающего процесса юзербота. Поэтому код видит Telegram-клиент, сообщение-команду, реплай, базу и функции Heroku. Не надо импортировать их вручную.

Пишите команду, после неё обычный Python. Значение выражения выводится автоматически. print() тоже перехватывается и показывается отдельно. Можно использовать await прямо в строке, например для запроса к Telegram.

примеры в Избранном
.e 2 + 2
.e "hello".upper()
.e await client.get_me()
.e print("строка вывода")
.e await message.edit("готово")

Первая команда вернет 4. Вторая строку HELLO. Третья запросит профиль текущего аккаунта. Четвертая покажет напечатанный текст. Последняя отредактирует ваше сообщение-команду.

Важно: это не песочница

Код в .e исполняется внутри Heroku с правами процесса. Он может отправлять сообщения, читать базу и обращаться к файлам сервера. Не запускайте код от незнакомых людей, даже если он выглядит как пара безобидных строк.

пиши реплаем на нужное сообщение

r.raw_text может быть None, поэтому в подсчёте стоит or "". r.file.name вызовет ошибку, если файла нет. r.sender бывает не загружен: для имени попробуй await r.get_sender(). Кнопки через r.click(...) нажимай только на доверенных сообщениях. Некоторые кнопки запрашивают телефон, геолокацию или пароль 2FA; для них API требует явно указать соответствующие аргументы. Обычный клик можно выбрать по индексу click(0) или точному тексту click(text="Да").

Если написать просто .e реплаем на сообщение, содержащее код, Evaluator попробует исполнить текст реплая. Проверь, что там написано, до запуска.

Вывод, ошибки и флаги

  • Результат последнего выражения показывается автоматически
  • Текст из print() перехватывается, после результата показывается время исполнения
  • При ошибке Heroku присылает traceback, смотри последнюю строку, там обычно причина
  • Номер телефона, строка сессии, токены и адреса баз маскируются в выводе. Это страховка от случайного показа, а не повод выводить секреты
  • db.set("heroku.security", "owner", ...) блокируется защитой Evaluator

Флаг -so исполняет код без ответа:

.e -so await r.delete()

Свой модуль

Модуль это Python-файл с классом-наследником loader.Module. Отправляешь файл в Telegram и отвечаешь на него .loadmod. Перезапускать Heroku обычно не приходится.

Минимальный пример

hello.py
from heroku import loader, utils


@loader.tds
class HelloMod(loader.Module):
    """Отвечает приветствием"""

    strings = {"name": "Hello"}

    @loader.command()
    async def hello(self, message):
        """Поздороваться"""
        await utils.answer(message, "Привет")

В .help появится модуль Hello и команда .hello. Строка в тройных кавычках под методом служит описанием команды. Другой способ регистрации: назвать метод hellocmd, тогда суффикс cmd будет отброшен.

Работа с сообщениями

В message приходит само сообщение с командой. utils.get_args_raw(message) вернет весь текст после команды, а utils.get_args(message) разобьет аргументы на слова. Реплай получаешь через await message.get_reply_message().

фрагмент модуля
@loader.command()
async def wordscmd(self, message):
    """Посчитать слова в реплае"""
    reply = await message.get_reply_message()
    if not reply:
        await utils.answer(message, "Ответь на текстовое сообщение")
        return
    await utils.answer(message, str(len((reply.raw_text or "").split())))

Имя метода wordscmd дает команду .words. Это удобно, если ты привык к старым модулям Hikka.

Настройки и сохранение данных

Если пользователю надо менять параметр через .config, объяви его в конструкторе:

фрагмент модуля
def __init__(self):
    self.config = loader.ModuleConfig(
        loader.ConfigValue(
            "greeting", "Привет", "Текст ответа",
            validator=loader.validators.String(),
        ),
    )

Читается как self.config["greeting"]. Валидаторы проверяют тип: есть Boolean, Integer, Float, Choice, Series, Link и другие. Если нужно просто запомнить значение для самого модуля, есть self.set("ключ", значение) и self.get("ключ", значение_по_умолчанию). Эти данные переживают перезапуск.

Ватчер и фоновый цикл

Команда срабатывает по запросу владельца. Ватчер вызывается при сообщениях и может реагировать сам. Теги отбирают нужные события:

фрагмент модуля
@loader.watcher("in", "only_messages", "no_commands")
async def watcher(self, message):
    if "привет" in (message.raw_text or "").lower():
        await message.reply("Привет")

@loader.loop(interval=300, autostart=True)
async def ticker(self):
    await self.client.send_message("me", "Прошло пять минут")

in оставляет входящие сообщения, only_messages убирает служебные события, no_commands исключает команды юзербота. loader.loop запускает метод по интервалу в секундах. Не стоит делать ватчер, который отвечает на каждое сообщение без ограничений: так недолго поймать FloodWait.

Меню на кнопках

Их отправляет персональный инлайн-бот, который создается при первом входе:

фрагмент модуля
async def pressed(self, call):
    await call.answer("Готово")
    await call.edit("Кнопка сработала")

@loader.command()
async def menucmd(self, message):
    """Открыть меню"""
    await self.inline.form(
        text="Меню",
        message=message,
        reply_markup=[
            {"text": "Нажать", "callback": self.pressed},
            {"text": "Закрыть", "action": "close"},
        ],
    )

Колбэк получает call. Через него можно ответить на нажатие, изменить сообщение, удалить или выгрузить форму. У кнопок бывают callback, url, input и готовые действия вроде close.

Шапка файла и совместимость

Загрузчик читает несколько строк в начале модуля. Например:

начало файла
# meta developer: @username
# requires: requests
# scope: heroku_min 2.1.0

__version__ = (1, 0, 0)

Автор попадет в справку, пакет из requires загрузчик попробует поставить через pip, а heroku_min не даст поставить модуль на старое ядро. Импорты telethon, hikkatl и hikka внутри сторонних модулей Heroku перенаправляет на herokutl и heroku. Поэтому старые модули часто работают без правок, хотя проверять всё равно стоит.

Рабочие примеры находятся в папке heroku/modules/. Начни с translate.py и test.py: там хорошо видно, как команда получает сообщение и как отвечает.

Если одной страницы мало

loader.Module даёт доступ к Telegram-клиенту, базе и инлайн-менеджеру. Для списков и галерей есть self.inline.list(...) и self.inline.gallery(...), для перевода строк интерфейса модуль может задать strings_ru. Внешние общие библиотеки подключаются через self.import_lib(url), библиотечный класс наследует loader.Library и оканчивается на Lib. Удобные методы вроде utils.escape_html и utils.get_chat_id лежат в heroku/utils/. Подписи аргументов и примеры вызывающих модулей смотри в исходниках той же ветки, на которой запускаешь свой код.

Beta

Тестовая ветка следующей версии. На момент проверки origin/beta и origin/dev указывали на один и тот же коммит dba41c58. Разницы в коде между ними сейчас нет.

Для чего она существует

На beta попадают изменения до выхода в master. Сейчас возможности и проблемы у нее те же, что на dev. Смысл beta для пользователя в том, чтобы проверить следующий релиз заранее, пока он еще не стал стабильным.

Плюсы beta

  • Новые возможности раньше master
  • Исправления некоторых багов, которые еще не доехали до стабильной версии
  • Можно проверить свои модули перед следующим релизом

Минусы beta

  • Проверка списка тестеров при запуске и попытка сброса на master без допуска
  • Новые изменения могут сломать старый модуль
  • Временные зависимости, например herokutl==2.2.0.dev2
  • Некоторых команд master больше нет

Можно ли просто поставить

Для dev и beta предусмотрена проверка списка тестеров. При запуске код получает список id из coddrago/modules-web. Если id нет в списке и текущая сборка не входит в историю origin/master, функция пытается сбросить ветку на master и перезапустить Heroku.

В коде есть ошибка

После сброса функция пытается вызвать self.client.log_out(), но объект запуска не создает self.client. Исключение перехватывается. Поэтому в изученном коммите разлогин не гарантирован, а вот откат рабочей папки и перезапуск могут произойти. Перед экспериментами сделай резервную копию своих изменений.

Ветка dev

Ветка разработки. В изученном коммите версия 2.2.2, зависимость herokutl 2.2.0.dev2. Ветка beta сейчас указывает на тот же код; деление на «разработку» и «тестирование» здесь объясняет, зачем обычно выбирают эти имена, а не техническую разницу между ветками.

Кому какую ветку брать

ВеткаКому подойдетГлавный компромисс
master, 2.1.0Хочешь просто пользоваться каждый деньНет новых функций, пока не вышел релиз
beta, 2.2.2Есть доступ к тесту, хочешь проверить следующий релизИзменения могут ломать привычное поведение

Плюсы dev

  • RichText в сообщениях и формах
  • Несколько префиксов и личные префиксы для совладельцев
  • Защита секретов в логах и приватности служебного канала заметно лучше
  • Удобнее работать с несколькими аккаунтами и логами модулей

Минусы dev

  • Без допуска бета-тестера ветка может откатиться на master и перезапуститься
  • Временная версия herokutl, которую могут менять вместе с ядром
  • Пресеты удалены, часть старых команд исчезла
  • Новые функции модулей могут не работать на master

Что изменилось в использовании

Несколько префиксов

На master у владельца один префикс. На dev можно задать несколько, первым будет основной:

в Telegram
.setprefix . ! ?

После этого понимаются команды с точкой, восклицательным и вопросительным знаком. Есть и персональные префиксы для пользователей, которым ты уже выдал права, например через .setprefix --user 123456789 !. По умолчанию длинные префиксы по-прежнему требуют настройки allow_nonstandart_prefixes.

Одинаковые команды в разных модулях

Если два модуля предлагают одну команду, загрузчик больше не перезаписывает ее молча. Показывается выбор, чью версию команды оставить. Особенно полезно, когда ставишь несколько модулей для одной и той же задачи.

Кеш и обновление модулей

Загруженные модули кешируются локально, чтобы не качать их повторно без нужды. Для изменения обычного стороннего модуля загрузчик предлагает обновление, если ты не разрешил всегда обновлять этот URL. Встроенные обновления и URL из списка always_update_modules идут без нового подтверждения. Если вручную редактируешь кеш или скачанный файл, придется следить, откуда загрузчик берет следующую копию.

RichText

В карточке .ping, справке, информации о боте и переводе поддерживаются новые богатые сообщения Telegram. В .config некоторых модулей появился rich_mode. Модули могут отправлять форму через self.inline.form(..., rich_message=...) и менять ее через InlineMessage.edit(rich_message=...). Если клиент или чат не поддерживает формат, код пытается перейти на обычный текст с медиа.

Терминал

Пароль sudo вводится через инлайн-форму и передается процессу в stdin. Больше не надо редактировать сообщение в Избранном. Команде .terminate добавили короткий алиас .kill.

Логи

Логи теперь разделяются по аккаунтам, если Heroku работает сразу на нескольких сессиях. Команда .logs умеет фильтровать записи конкретного модуля. Значения из реестра секретов автоматически вырезаются из сообщения об ошибке и файла лога. Всё равно просматривай лог перед отправкой в публичный чат, цензура не может угадать каждую строку, которую придумал сторонний модуль.

Что изменилось под капотом

  • Строка сессии, номер телефона и токены регистрируются как секреты. При форматировании лога Heroku их маскирует
  • Файлы базы и конфигурации записываются через временный файл с закрытыми правами 0600, каталог сессий получает права 0700; файловый лог тоже закрывается от других пользователей системы
  • Сервисный канал проверяется перед повторным использованием. Если он стал публичным или перестал быть вашим, бот создаст новый вместо отправки бэкапа посторонним
  • Для прокси через Unix-сокет нужна явная переменная HEROKU_ALLOW_INSECURE_PROXY=1; проверяются владелец и права сокета
  • Загрузчик осторожнее проверяет URL модулей, а debug-лог сырых MTProto-пакетов убран
  • loader.ConfigValue регистрирует значения валидатора Hidden как секреты
  • У модуля появился self.create_task(coroutine). Созданные через него фоновые задачи закрываются при выгрузке модуля
  • Из кода убрана телеметрия _send_stats
  • Из requirements.txt убраны aiofile, aiofiles и bs4

Что пропало и может удивить

Модуль presets.py удален целиком: больше нет .presets, .loadpreset, команд папок модулей и загрузки алиасов из файла. Конфигуратор изменился внутри, но привычная .cfg Модуль поле значение на dev по-прежнему работает. Убрали лишь старый алиас .fcfg.

Если что-то не работает

Начни с терминала и .logs. Последняя строка ошибки обычно полезнее, чем скриншот главного меню.

Heroku не запускается под root

Работай под обычным системным пользователем. Если root нужен намеренно, запусти python3 -m heroku --root. Тогда сторонние модули тоже получат права root.

Требуется Python 3.10 или новее

Проверь python3 --version. Установи новую версию Python и пересоздай виртуальное окружение именно ею, например python3.11 -m venv .venv. Затем снова установи зависимости.

Check that this is the only instance running

Файл сессии занят другим процессом. Не запускай Heroku второй раз поверх уже работающей. Если используешь screen, вернись в старый сеанс через screen -r heroku. Путь к занятому файлу программа пишет в логе.

Неверные API ID или hash

Сверь оба значения на my.telegram.org. Номер и hash должны быть от одного приложения. Удали ошибочный config.json и запусти настройку заново. Файл сессии удалять для этого не нужно.

Telegram выдал FloodWait

Это лимит Telegram, не ошибка установки. В сообщении указано, сколько ждать. Не повторяй попытки входа одну за другой, так ожидание может вырасти.

Сессия перестала работать

Проверь в Telegram список устройств: не завершал ли ты нужный сеанс. При использовании одной и той же сессии одновременно на двух машинах Telegram также может ее отозвать. Придется войти заново.

Инлайн-бот не создался

У аккаунта может быть лимит ботов в @BotFather или временное ограничение на их создание. Можно выбрать готового бота через .ch_heroku_bot <имя> и .ch_bot_token <токен>. Держи токен в тайне.

Команды молчат

Проверь, работает ли процесс, затем отправь команду от того же аккаунта, под которым авторизована Heroku. Возможно, ты сменил префикс или внес чат в черный список. Текущий префикс показывает /profile у инлайн-бота.

Модуль не загрузился

Открой .logs. Там будет конкретная причина: отсутствие библиотеки, несовместимая версия Heroku, ошибка самого модуля или не настроенный инлайн-бот. Если проблема касается одного модуля, сначала отключи его, а не сбрасывай весь бот.

Хочу начать с нуля

Сначала сохрани нужные данные через .backupall. Запуск python3 -m heroku -w предложит удалить конфиги, сессии и установленные модули. Это полный сброс с повторным входом в Telegram. Для сброса только базы используй .cleardb.

Куда писать за помощью

Команда .support покажет ссылки на чаты проекта. Перед отправкой .logs посторонним прочитай файл: некоторые сторонние модули пишут в лог собственные секреты.
